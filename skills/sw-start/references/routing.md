# Routing

Resolve the named item before choosing an action. Read the fresh graph board, not a
scope-wide priority rule. A public skill explicitly requested by name retains that
request and checks its prerequisites.

| Evidence | Route |
| --- | --- |
| No workspace | Confirm layout/setup, then the requested ingest or shape action. |
| Missing/incompatible graph schema | Show the upgrade dry-run and obtain agreement before migration. |
| Stale current graph | Rebuild through bounded maintenance; do not call this a workspace upgrade. |
| Several active candidates | Show board and ask which item, even at the same station. |
| One reserved accepted feature | sw-spec, not started. |
| Named draft, including open questions | sw-spec. |
| Named submitted feature or invalidated approval | sw-review; only verified evidence promotes. |
| Reviewed feature without a current passing plan/tasks | sw-plan. |
| Passing plan, no publication request | Markdown complete; stay in plan. |
| Explicit publication request with current passing gates | Offer sw-publish; exact PUBLISH confirmation still required. |
| Published feature without tasks or with task-only changes | sw-plan; never poll Jira. |
| Published-text amendment | Stop for current immutable supplied baseline and CR. |
| Draft epic/reopened slice | sw-shape. |

Stored destination preferences never authorize writes or force publication. Ordinary
local completion asks no destination question; explicit ambiguous publish/ship asks
Markdown, Jira or both under the standing rules. Archived IDs remain tombstones.
