# Questions that expose consequential choices

Read evidence first. Sort unanswered questions by whether they block a safe decision,
then by likely rework cost. Ask no more than five at once. Always offer alternatives
and consequences; make the unanswered default explicit and safe.

Format:
Q-NNN [blocking or nonblocking] — question
A) choice → consequence; B) choice → consequence; C) defer → consequence.
Default if unanswered: retain uncertainty and do not approve dependent work.
Owner: role. Due: agreed date or Unknown. Evidence checked: source IDs and locations.

Useful prompts:
- Which actor experiences the problem: customer → self-service value; support →
  assisted workflow value; both → separate contexts and potentially separate slices?
- What counts as a refund request's useful result: recorded pending request → no
  payout promise; completed payout → approval and settlement also enter scope?
- Which window governs: 14 days → amend conflicting policy; 30 days → redefine
  percentage tiers; exception path → fund a manual decision process?
- What makes a request complete: whole order → simpler amount basis; selected items
  → define allocation and prior returns before estimating?
- How are elapsed days counted: local calendar dates → midnight boundaries; elapsed
  24-hour periods → timestamp dependency? Default: no boundary approval until decided.

Record the question before asking. On answer, retain options and append answer,
respondent role/name, date and evidence URL in the same Q record. Link an accepted
policy choice to a DEC record. A Q answer is not a global sign-off on the story.
Do not ask for identity details or confidential information merely to fill a template.
