# E04 Accounts, sign-in and keys

## Goal

Keep all of the user's identities and platform sign-ins in one safe place, for many platforms and many accounts at the same time.

## Scope

**In scope**

- Account list, adding accounts by hand or by sign-in, tokens, self-hosted servers, SSH keys, commit signing, HTTPS credentials.

**Out of scope**

- Choosing which account signs a commit (see E05). Managing users on the platform.

## Features

### F04.05 Self-hosted servers and certificates

**Priority:** Must · **Release:** R3 · **In mockup:** no · **Needs:** [F04.04](#f0404-connect-with-an-access-token)

**User story.** As a company developer, I want to connect to our own server, so that I can use GitLanes at work.

**What it does**

- Enter the server address, including a port or a sub path.
- The app detects the platform type and version and says which features that version supports.
- Custom certificate authorities and a proxy can be used (see F11.09).

**Business rules**

- **BR1.** The app never offers to turn certificate checks off.
- **BR2.** An address must use a secure connection. A plain connection is only allowed after a clear warning, for local test servers.

**Empty, loading and error states**

- Cases: server not reachable, certificate not trusted, not a supported platform, version too old.

**Acceptance criteria**

- [ ] **AC1.** Given a server with a company certificate that the system trusts, then connecting works without extra steps.
- [ ] **AC2.** Given an unsupported version, then the app names the lowest supported version.

### F04.06 Test and repair a connection

**Priority:** Should · **Release:** R3 · **In mockup:** yes · **Needs:** [F04.04](#f0404-connect-with-an-access-token)

**User story.** As a user, I want to check an account, so that I know why something does not work.

**What it does**

- "Test" checks sign-in, rights, expiry and, for SSH, the key with the server.
- A failed check shows the failed step and one clear fix.

**Business rules**

- **BR1.** A test never changes anything on the server.

**Acceptance criteria**

- [ ] **AC1.** Given a working account, then the result says it works and lists the user name seen by the server.
- [ ] **AC2.** Given a revoked token, then the result says so and offers "Sign in again".

**Mockup:** Accounts page, "Test". Actions: `toast`.

### F04.07 Default account and removing accounts

**Priority:** Must · **Release:** R1 · **In mockup:** yes · **Needs:** [F04.01](#f0401-accounts-page)

**User story.** As a user, I want to choose a default and remove old accounts, so that new repositories behave as I expect.

**What it does**

- "Make default" moves the default mark.
- "Remove" asks for confirmation and lists the identity rules and repositories that use this account.

**Business rules**

- **BR1.** Removing an account deletes its secrets from the key store.
- **BR2.** Rules that point to a removed account are shown as broken until fixed. They are never moved to another account silently.
- **BR3.** Past commits are not changed.

**Acceptance criteria**

- [ ] **AC1.** Given an account used by 2 rules, when the user removes it, then the dialog names both rules first.
- [ ] **AC2.** Given a new default, when a repository has no matching rule, then the new default signs it.

**Mockup:** Accounts page. Actions: `toast`.
